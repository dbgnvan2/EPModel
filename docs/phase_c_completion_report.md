## 4. Changes made after the constants were frozen

No constant's *value* changed after the freeze (`constants_frozen.md`, 2026-10-07). One constant's *unit* did:
`ensemble_precision` is now measured against the pooled sd of the two arms (§10), logged post hoc in
`constants_changes.md`, its only entry after the freeze. These code changes came after the freeze, and each is
reported here:

1. **Three numerical fixes to the policy** (step 14). The first ensemble runs crashed. Each fix has a unit test
   proved failing by reverting the fix:

     finite: `test_m4d1_large_learned_values_keep_the_softmax_finite`;
   - `WITHHOLD` has no weight when no automatic act has any:
     `test_m4d1b_nothing_to_withhold_when_no_automatic_act_has_weight`;
   - the withheld act is drawn from the automatic channel's own within-channel weights, which stay defined when
     the mixing weight gives that channel no share:
     `test_m4d1b_withheld_act_is_drawn_when_the_automatic_channel_has_no_share`.

   None of these was chosen against a criterion. They change behaviour only where the old code crashed or
   divided by zero.
2. **`M11.C.25`'s readout was corrected after its mutant survived.** It first read "the female spouse is
   dominant". The arms differ only in which spouse is female, so a sex bias raises that readout in both arms
   alike, and the paired difference cannot move: the test could not fail. It now reads "the first spouse is
   dominant", which a sex bias does move when the sexes are swapped. The verdict is PASS both before and after.
   The fix makes the test able to fail, and it now fails under the sex-term mutant.
3. **The criterion roles moved to config** (`config/bowen/criterion_roles.md`). `M2.3a` forbids a person's id
   in Python source, and the criteria named Ravi, Marta and Nadia. Behaviour did not change: the verdicts were
   identical before and after.
4. `hold_gain` = 0.3 was chosen at step 8 against `M5.D.3`'s "abort is the usual first outcome". It is logged in
   `constants_changes.md` and was chosen before the freeze.

**One incident during the run.** At step 15 a policy mutation check rewrote `src/bowen/policy/policy.py` in

## 10. The precision rule — decided 2026-10-08, before rerunning

The owner asked for a decision on the stopping rule's precision, which `M11.C.16` turns on. **Decided: the half-width
is compared with `ensemble_precision` (0.25, unchanged) times the *pooled* seed-to-seed sd of the two arms,
√((sd_baseline² + sd_treatment²) / 2), instead of the baseline arm's sd.** When both arms have no spread, the
differences' sd is used, as before. The margin (`M17.A.4`) and the equivalence bound stay relative to the baseline
arm's sd, as plan D8 approved. D8 governs margins. That precision used the same scale was the build's choice, not
the plan's.

Why. `M17.A.1` asks for enough seeds that the interval is narrow; δ is `[I]` and its unit is not given.

- *The baseline arm alone is the wrong ruler when the arms differ in spread.* In C.16, lowering level makes the
  treatment arm far more variable: the baseline sd is 0.027, while the per-seed difference's sd is 0.134. The
  interval, −0.063 ± 0.012, lies far beyond the margin, 0.0027, but never reaches 0.25 of the baseline's sd.
- *The ruler must not depend on which arm is called baseline.* For `M11.C.38`'s adjacent pairs and `M11.C.41`'s
  cells the label is arbitrary, and a baseline-only scale changes the stopping point when the arms are swapped.
  A pooled scale does not.

Rejected:

- *The differences' own sd* (the option `TODO.md` named). The half-width over its own sd is 1.96/√n, so the rule
  would be a fixed seed count (here, 100) in disguise — what `M13.4` replaced. The record shows this exactly: every
  criterion that stopped at n = 100 has half-width / difference-sd = 0.196.
- *Raising the cap.* It is a frozen constant, and C.16 would need about 1,500 seeds.
- *Stopping once the interval clears the margin.* Stopping on the outcome at up to ten looks inflates false
  positives.

This changes when every criterion stops, not only C.16, so all three records are rerun and every verdict that moves
is reported here. No constant's value changes; `ensemble_precision`'s unit changes, and that is logged in
