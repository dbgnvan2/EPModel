# Part 1: Hot-Blooded vs Cold-Blooded

## Reader report: Fu, ""Hot-Blooded" vs "Cold-Blooded": Simulating the Behavioral Phenotypes of Childhood Aggression via Generative Agents", arXiv 2610.11951v1

**1. Simulation formalism** [PAPER] — Four persona-conditioned LLM agents run in a fixed **4-turn interaction chain**
(initial reaction → peer response → agent action → final reflection); the peer ("Leo") is "generated by the same
language model but operated independently," conditioned on the focal agent's preceding behavior (Methods/Procedure).
DeepSeek-V3, temperature fixed at T = 0.7 (explicitly non-deterministic). 1,920 runs = 4 agents × 3 replications × 8
scenarios × 20 seeds. [INFERENCE] — No scheduling/update-scheme formalism transfers: turn-based LLM dialogue, not a
typed-event engine. The nested "3 replications × 20 seeds" is not decomposed into within-run vs across-seed variance
in the analysis (they pool to n = 60 per cell), so it offers no seeding discipline EPModel lacks.

**2. Agent architecture** [PAPER] — Each agent is a 5-parameter persona on a 0–1 continuum (dispositional anger, anger
control, hostile attributional bias, empathy/emotional regulation, aggression instrumentality), explicitly
"theory-driven ordinal boundaries" rather than "empirical epidemiological estimates" (Methods/Agent Construction,
Table 1). Parameters "served two functions: guiding the LLM's role-playing prompt and computing internal emotion
updates." Trait descriptions "remained invariant across all scenario vignettes." [INFERENCE] — The ordinal-boundaries
framing is convergent with EPModel's "directions/orderings, no magnitudes" stance (already covered, see B). No
learning, adaptation, or bounded-rationality content.

**3. Interaction/network structure** [PAPER] — None. A single peer plus vignettes; no network, no dyad dynamics, no
influence/cascade. Not transferable.

**4. Initialization** [PAPER] — Four hand-set profiles derived from the SIP model (Table 1), invariant across trials;
no variation of or sensitivity analysis over initial attributes. [INFERENCE] — Confirms (negatively) the design-lessons
point that un-varied initial conditions hide sensitivity; adds nothing.

**5. Calibration and validation** [PAPER] — Construct validity via three criteria: discriminant validity (Welch's t,
Bonferroni, Cohen's d), cross-seed reliability (two-way random ICC with **seed as rater**, 20 seeds; CV = SD/M),
convergent validity with narratives (Results). 32 indicators (26 continuous 0–10, 4 count, 2 composite; Table 3).
Effect sizes large to very large: retaliation d = 8.27, anger d = 4.18 (reactive), prosocial behavior d = −17.80,
affective empathy d = −13.39 (proactive) (Table 4, Fig. 3). **No quantitative human benchmark** — the human arm is
qualitative (interviews/focus groups), so all magnitudes are internal comparisons. [INFERENCE] — The ICC-with-seed-as-
rater and CV machinery are the transferable piece (see HB-1). Effect sizes near ±18 are a manipulation check against a
deliberately different profile, not a discovery.

**6. Reported failure modes / limitations** [PAPER] — Three, named: (1) single foundation model (DeepSeek-V3 only);
(2) **hyper-consistency / over-discreteness** — agents "cleanly differentiated all eight scenarios, human interview
data exhibited adequate scenario discrimination in only five," and "explicit persona conditioning may over-amplify
discrete theoretical boundaries that remain naturally fluid… in real-world human populations"; (3) hypothetical
vignettes "fail to capture the real-time, emergent complexities of dynamic social interactions" (Limitations). Also:
four count-type indicators had poor reliability (ICC 0.08–0.39) while continuous ratings were mostly ≥ 0.9 (Table 4);
CV was highest for proactive (1.95) and co-occurring (1.35) agents in provocation/moral scenarios (Fig. 1).
[INFERENCE] — The over-discreteness limitation is the substantive transfer (see HB-2).

**7. Software engineering** [PAPER] — Concordia framework ("modular architecture—identity, associative memory,
generative reasoning"); a **hybrid blind-coding pipeline**: behaviors generated by persona-conditioned agents but
"evaluated via neutral, theory-blind coding prompts," positioned explicitly as mitigating the "circularity problem"
and confirmation bias (Discussion). No logging/observability/reproducibility content beyond seeds. [INFERENCE] — The
generate/evaluate separation is the same principle as EPModel's arm-blindness (C35); no new engine lesson.

**8. Small-N / emotion / family / horizon** [PAPER] — Small-N (4 agents), rich emotion (anger, affective vs cognitive
empathy, arousal), childhood. **No family/household unit, no long horizon** (single-vignette, 4 turns, no time). Two
substantive findings: (a) **reactive aggression keeps empathy/prosocial behavior intact** — Alex's affective empathy
(8.20) and prosocial behavior (8.55) stay near baseline while anger (7.32) and retaliation (7.43) rise, so hot
reactivity is arousal + misreading, *not* callousness (Results/Divergent Validity); (b) **cognitive/affective empathy
dissociate** in the proactive agent — accurate reading of others paired with near-zero affective response ("visible
prosocial behavior is instrumental, not authentic," Table 1). Forgiveness "helps prevent revenge… significantly
reduces anger" (Introduction) is cited but not tested. Future work names multi-agent roles (victims, followers,
bystanders, teachers).

**Not transferable / cautions** — The SIP five-stage model is a *different theory* from Bowen; its stage-specific
distortions do not belong in a Bowen consistency engine. Turn-based peer dialogue and scenario vignettes have no
analogue to EPModel's typed events and nodal-event spells. The entire paper is an LLM-persona demonstration (single
model, T = 0.7, no rule-based control arm), so every "reliability" number is about sampling stochasticity around a
fixed prompt, not about a deterministic mechanism. All effect sizes are measured against a hand-chosen opposite
profile, so none calibrate anything.

### HB1 — Per-readout cross-seed reliability, reported per arm and per condition; discrete readouts flagged

**Proposed requirement.** The ensemble runner (Phase E) **MUST** report, for each quantitative readout used by any
`M11.C` criterion, a cross-seed reliability coefficient computed with seed as the rater over the ensemble, **reported
separately per arm and per scenario/condition** — never a single pooled number. Readouts that are **count- or
event-type** (e.g. `CUTOFF` occurrence, symptom counts, which-tie-ruptures-first) **MUST** be reported with an explicit
replication note when their coefficient falls below a declared floor, because discrete readouts are expected to be
systematically noisier than continuous ones; the floor and the coefficient's cutoffs **MUST** be declared in `M10` and
graded `[I]`.

**Where it would live.** Phase E: ensemble runner / counterfactual arms (readout layer), with the per-seed raw material
already in the `M16` run log.

**Evidence.** Results, "Cross-Round Reliability" (Table 4, Fig. 1): ICC with seed as rater (20 seeds); 21 indicators
≥ 0.75, but the four count indicators fell to ICC 0.39/0.17/0.11/0.08 while continuous ratings hit 0.90–0.99; CV varies
by subtype and scenario (reactive 0.19–0.44 vs proactive up to 1.95). SHOWN for the ICC/CV pattern; the
discrete-readouts-are-noisier transfer to EPModel is INFERENCE.

**What it changes.** Adds a reporting rule; inference validity. It extends design-lessons §2.6's "separate the variance
sources" (which decomposes variance) with a *per-readout* reliability coefficient, and gives the rare-move-coverage
concern a concrete number: EPModel's count-type readouts are exactly the class the paper finds unreliable. A criterion
that reads cleanly on a continuous quantity but is noise on a discrete one is exposed rather than averaged away.

**Cost/risk.** Low — read-only over ensemble outputs, no engine change. No conflict with M3.D.4/M3.D.5 (Phase E),
M3.D.6, or M16.B. The ICC cutoffs (Koo & Li) are borrowed reporting conventions and must be labelled `[I]`, not treated
as model constants. No fitting.

### HB2 — Over-discreteness flag: near-perfect arm separation must be reported as a warning, not support

**Proposed requirement.** For every `M11.C` direction criterion, the report **MUST** state the overlap between the two
arms' per-seed readout distributions (at minimum the fraction of seeds in which the arm ordering is not strict), and
when the distributions are disjoint across all seeds — or a readout shows zero within-arm seed variance — the report
**MUST** flag the result as *possibly over-discrete*: a mechanism more sharply bounded than the theory warrants, and
**MUST NOT** describe such a result as strong support on the strength of its effect size alone.

**Where it would live.** M11 (acceptance tests, reporting side) or Phase E readout layer; the overlap check rides on the
same per-seed distributions HB1 produces.

**Evidence.** Limitations: agents "cleanly differentiated all eight scenarios" against five for humans; "explicit persona
conditioning may over-amplify discrete theoretical boundaries that remain naturally fluid"; "the simulation appears to
over-discriminate… hyper-sensitivity under neutral conditions." ARGUED (authors' own limitation statement); the mapping
to a rule-based deterministic engine is INFERENCE.

**What it changes.** Adds a reporting rule; inference validity. It is the mirror image of §2.6's "pre-declared minimum
effect size" (too-narrow CIs make everything significant): here *zero-overlap* separation is itself the warning sign,
because a Bowen mechanism whose arms never overlap is more discrete than any family process warrants. It complements,
without duplicating, `M11.4e` (statistic defined under zero-variance arms) and C34's null/homogeneous arm (whether a
null condition still passes) — HB2 asks whether a *real* condition passes too cleanly.

**Cost/risk.** Trivial — a distribution-overlap check on already-computed per-seed values. No conflict with
M3.D.4/M3.D.5, M3.D.6, M16.B, or M11.F.9. No new constants beyond a declared "disjoint" definition, which is a
reporting convention not a model constant.

**Already covered (not written up).** Theory-driven ordinal boundaries → spec §0 / `M0.4` / `M11.4c` / `M15.B`.
Hostile attribution / "hearing as critical" → `M4.C.5` plus `M9.2`/`M9.7`. Cognitive-vs-affective empathy split →
convergent with `M5.F` and `M9.5`; no new mechanism, and the SIP theory is out of scope. Blind-coding/circularity guard
→ C35 arm-blindness.

# Part 2: MASC

## Reader report: Peng, Jiang, Zheng, Yang & Chen, "MASC: A Multi-Agent Self-Calibration Framework with Latent Construct Alignment for Consistent Client Role-Playing in Psychological Counseling", arXiv 2610.08250v1

MASC is an LLM multi-agent loop that keeps a simulated counseling *client* psychologically coherent across a multi-turn
session by predicting target latent constructs, generating/refining candidates, verifying them by judge voting, and
feeding mismatches back as retry memory. It is evaluated by CRPC-Bench, a two-level benchmark (session-level stable
constructs + turn-level evolving constructs) built on 38 motivational-interviewing client profiles. The closest thing to
EPModel is not the LLM machinery but its **rule-based bone structure**: a gated ordinal state machine and a
slow-variable-gated action prior, both sitting *outside* the LLM.

**1. Simulation formalism.** Turn-synchronous: at turn *n* it observes `Hn` (history + current counselor utterance),
predicts turn-level targets `zn=[EE,PS,CA]` (emotion, psychological state, communicative action), then generates and
verifies a response through at most 3 attempts × 5 debate steps (Algorithm 1, Eq 1). Two timescales are explicit:
session-level `C_sess=[PI,BFT]` (profile + Big Five) persist; turn-level `zn` evolve. The psychological-state transition
is a **deterministic gated rule**, not LLM output (Eq 3): Precontemplation→Contemplation only if the target motivation
topic is addressed *and* matched; Contemplation→Preparation only if all belief barriers are resolved; otherwise the
state **persists**. Communicative action is sampled from `p(a) ∝ p_ctx(a) + p_rec(a)`, where `p_rec(a)=p(a|ρ)` is a prior
over the action set conditioned on receptivity ρ∈{1..5} that "discourages a low-receptivity client from moving
prematurely" toward Acknowledge/Accept/Plan (Eq 4–6). [PAPER] [INFERENCE: the gated-state-machine + slow-variable-gated-
prior pattern is the one directly precedential structure for EPModel's rule-based core; the two-timescale split matches
EPModel's slow/fast design.]

**2. Agent architecture.** Four components in a closed loop: latent-construct discriminator, multi-agent debate generator
(K=3 agents, L=5 steps, peer revision, Eq 7–8), voting calibrator (K=3 judges, majority vote, τ=2/3), retry memory (B=2
most recent failure records, Eq 16). The calibrator separates **judge agreement** (reliability, Eq 12–13) from **target
matching** (accuracy, Eq 14) and selects on agreement first, matching second (Eq 15). Heterogeneity: MASC(Homo)=Qwen
ensemble, MASC(Hetero)=ChatGPT-5.5+Minimax-M3+Deepseek-v4-pro; Hetero is "strongest in aggregate" but does not dominate
every trait (Extraversion goes to Homo, Fig 3). [PAPER]

**3. Interaction/network structure.** Single counselor–client dyad, one client at a time. The "multi-agent" is internal
to the client simulator (generation + judge agents), not a social system; debate agents revise against each other's
prior-step responses (Eq 8) with no persistent social structure. **Nothing on dyads/triads/networks.** [PAPER]

**4. Initialization.** Profiles come from the MI dataset (38 profiles): behavioral problem, initial/final stage of
change, persona, motivation, belief barriers, acceptable plans, receptivity 1–5, augmented with Big-Five High/Low and
utterance-level emotion labels. No sensitivity analysis of initial conditions is reported. [PAPER] [INFERENCE: below
EPModel's M15.D.4 standard.]

**5. Calibration and validation.** A **separate evaluator** relabels every method's full output under one protocol,
method names and generation sources hidden, compared to real dialogues by KL divergence (Tables 1–3). Session-level: 5
profile attributes, receptivity, Big Five; turn-level: Action/Emotion/State KL. Instrument validation: annotation
protocol 78.92% accuracy on PersonalityEvd, ~87.5% inter-annotator agreement on a 30% sample, emotion annotation 76.12%
on DailyDialog. Ablations (w/o Debate, w/o Voting+Memory, w/o Memory) all "retain the same three-Qwen backbone"; the
full loop is strongest, Debate removal causes the broadest degradation (−5.51 profile avg, −2.36 Avg MS, all three KL
worse, Table 3). **No seed ensembles, no variance reporting, no per-seed statistics.** Honest limits: MASC(Hetero) Avg
MS 19.55 "without matching the full depth of progression" (Real 27.56, Table 1); surface-overlap metrics
(BLEU/ROUGE/METEOR) demoted to auxiliary diagnostics because scenario divergence lowers overlap for valid dialogues
(App A). [PAPER]

**6. Reported failure modes / limitations.** Static profile prompting → persona drift, unrealistic cooperativeness,
premature change disclosure (Abstract/Intro). Two distinct failure modes at two levels: a dialogue may "preserve profile
facts while moving unrealistically quickly toward change, or produce plausible local reactions while gradually
contradicting the assigned role." Profile-Based baseline is fluent but contradicts its Big-Five cues. **Schedule-ST — a
fixed state-transition schedule (turns 1–10/11–20/21–30) — achieves the best baseline Emotion KL (0.33), beating the
full CSF framework (0.56) on that dimension** (Table 2). Convergence stats are success-conditioned: 73.97% of turns
reach 3/3; of those 55.81%/31.04%/13.15% in R1/R2/R3 — explicitly "not the probability that a retry repairs an
arbitrary failure"; and they "do not separate the contribution of stored mismatch feedback from the benefit of drawing
another stochastic sample." Remains "limited… by its reliance on automatic LLM-based evaluation" (Conclusion). [PAPER]

**7. Software-engineering lessons.** The sharpest one: "MASC's internal voting labels are not reused as its reported
scores" — generation guidance is kept distinct from experimental measurement by a separate blinded relabeling.
Ablations change only the named component. Prompts and algorithms fully documented (App C–D); retry memory bounded
(B=2) to cap prompt length. Convergence trajectories (Fig 4, Fig 5 heatmap) show *when* the loop converges.
[INFERENCE: the guidance/measurement separation is a sharper statement of EPModel's M16.B + M17.D.3.]

**8. Small-N / emotional / family / long-horizon.** Emotion is a discrete 7-label set (Ekman), kept separate from state
and action: "Emotional concern should not automatically be interpreted as readiness for behavioral change." Sessions
are 30 turns; state progression is a 3-state gated transition with persistence, not free drift. No family/household
content. [INFERENCE: the gated slow-state transition is a small formal precedent for Bowen-style gated change, but at 3
ordinal states over 30 turns — far below EPModel's decades.]

**Not transferable / cautions.** The multi-agent debate, voting calibrator and prompt templates are LLM machinery —
M3.D.6 already excludes them. No seed/reproducibility discipline (single observed run) — far below M3.D.4/D.5.
LLM-as-judge evaluation, validated only at 76–79% agreement and not against humans for the main readouts — design
lessons §3.4 already rejects LLM-as-judge. Single dyad, no family/triangle/decades content. The Homo-vs-Hetero
comparison is confounded (heterogeneity bundled with model family), so no clean attribution — and its Eq 3 gated stage
machine is the transtheoretical model, which is the counseling analogue of EPModel's existing quantum-jump gating
(M10.C.4a), not a new mechanism.

### MC1 — Scripted-trajectory control arm (a schedule null)

**Proposed requirement.** Phase E's control arms (`M17.D.1`) **MUST** include a **scripted-trajectory** arm in which
the slow variables a criterion's readout tracks (e.g. `functional_level`, symptom severity) follow a fixed, declared
timetable independent of all interaction, so a directional readout reproducible by a bare time trend is exposed. A
criterion whose asserted direction is also produced by this arm **MUST** be reported as **not discriminating** against
a mechanism-free schedule and **MUST NOT** be described as supported by the mechanism it credits.

**Where it would live.** M17 (extend `M17.D.1`'s arm list; companion floor via `M17.D.4`).

**Evidence.** MASC Table 2 — Schedule-ST, a fixed state-transition schedule, attains the strongest baseline Emotion KL
(0.33), beating the full CSF framework (0.56). **SHOWN.**

**What it changes.** Adds a control arm / test. Distinct from `M17.D.1`(a)'s no-interaction controls (which still run
the full policy and learning): a scripted arm *replaces* the slow dynamics, so any criterion it also satisfies is not
measuring the slow dynamics at all. Improves inference validity — a directional result becomes a property of the
mechanism, not of elapsed ticks.

**Cost/risk.** Low — reuses the `ScriptedSource` object (already in Phase B) to drive slow variables on a timetable. No
conflict with M3.D.4/D.5 (the script is deterministic); no LLM (M3.D.6 unaffected); no fitting (M11.F.9 unaffected — it
is a null arm, not a tuned parameter). The timetable is an `[I]` constant set and must be labelled; it enters as an
exogenous-spell sequence, which is already a declared arm channel under `M17.D.3`.

### MC2 — Readouts must not reuse decision-path intermediates

**Proposed requirement.** A criterion's readout (`M11.G`, `M16.A.9`, `M16` windowed aggregates) **MUST** be computed by
an observer over the `M16` event log or by an independent instrument, and **MUST NOT** reuse a quantity the decision
path (`M4` policy, `M6` consolidation, `M4.D.6` reinforcement) computed for selection or learning. Any readout that
reuses such an intermediate **MUST** be labelled **internal** and **MUST NOT** be reported as an experimental result.

**Where it would live.** M16 (run-log / readout sourcing), with a static check mirroring `M11.D.22`'s shape (readout
code must not import policy/consolidation modules).

**Evidence.** MASC §Consistency Assessment — "MASC's internal voting labels are not reused as its reported scores"; a
separate evaluator relabels all outputs under the same protocol with method names hidden. **ARGUED** (operationalized,
but the value of the separation is not itself measured).

**What it changes.** Adds a reporting rule. `M11.D.22` already stops the *engine* importing readout code; this stops the
*readout* importing decision-path state, so a criterion cannot silently report the mechanism's own intermediate (e.g.
the selection propensity vector or the reinforcement signal) as a result. `M16.A.9` already sources from event records,
so this generalizes an existing implicit practice into a rule + static check. Improves inference validity.

**Cost/risk.** Low — a rule plus a static import check. No conflict with determinism (M3.D.4/D.5), no LLM, no fitting,
constants unaffected. Compatible with and a strengthening of engine purity (M16.B): it extends "no side effects" to "no
reuse of internals."

**Already covered (not written up).** Gated ordinal state transition (Eq 3) → `M10.C.4a` + `M5.D` + hysteresis. Slow-
variable-gated action prior (Eq 4) → `M4.D.1a` mixing weight + `M5.D.2a` PREPARE + `M5.D.8`. Distribution-level readout
(KL) → `M16.A.9`/`M17.B.5`. "Emotion ≠ readiness" → `M11.F.6` + `M5.F.2b`. Success-conditioned statistics →
`M17.F.1`. Blinded evaluation → `M17.D.3` arm-blindness.

# Part 3: SPIN / Cognitive-Affective Personality Inference

## Reader report: Deng, Li, Ge, Zhang, Zhang & Jiang, "Enhancing LLMs with Cognitive-Affective Personality Inference for Simulating Human Social-Psychological Behavior" (SPIN), arXiv 2610.08328v1

**1. Simulation formalism.** [PAPER] SPIN is a three-stage, three-LLM-call pipeline (Eq. 2, Fig. 1, §4.1):
`DECIDE(ELICIT(COMPILE(x_p), τ), τ)`. COMPILE runs **once per participant and is cached**; ELICIT runs per trial or per
item-level condition; DECIDE runs once per trial (§4.1). Zero-shot, temperature 1.0, fixed decoding, "no
self-consistency voting or multi-sample aggregation" (§4.1). No time-stepping, no scheduling, no simultaneity, no
seeding. [INFERENCE] Nothing transfers to EPModel's clocks/ordering; this is a cross-sectional respondent simulator, not
a temporal agent model.

**2. Agent architecture.** [PAPER] The decision rule is a fixed causal order — "who the participant is precedes what the
situation activates, which in turn precedes what the participant does" (§4.5) — with **stagewise input restrictions**:
COMPILE is task-blind (profile only); ELICIT sees core + stimulus but "not the raw profile"; DECIDE sees "only the
elicited state(s) and the trial, with no access to either the core or the original profile" (§4.5). Each stage's output
"is finalized before the next stage begins, making the source of each behavioral decision explicit and traceable"
(§4.5). The core is `θ ∈ [0,1]^K` traits (K=5), a rule set R of (cue, tendency, strength) with participant-specific
cardinality 2–5, and a style summary; the state is `σ ∈ [0,1]^L` (L=6: arousal, conflict, social concern, trust,
perceived exploitation risk, self-protection drive) plus drivers/inhibitors/mode/rationale (§4.2–4.3, Table 3).
[INFERENCE] This is the CAPS disposition/state split, and EPModel already has it as its backbone: M1.A.7 (disposition)
vs M1.A.7a (state), M4.C.1 appraisal → M4.D policy. SPIN independently confirms the design, with numbers (§5.3):
removing elicitation costs 0.036–0.055 Avg., removing compilation 0.021–0.033 — **the state layer is the more
load-bearing stage**, matching EPModel's emphasis.

**3. Interaction/network structure.** [PAPER] None. Participants are independent; there is no dyad, group, tie,
influence, or cascade. [INFERENCE] Nothing transfers.

**4. Initialization.** [PAPER] Profiles are demographic/narrative participant descriptions; trait cores are *inferred*
per participant by the LLM, not sampled from a distribution (Appendix F shows 4 of 6 example participants share the
identical trait vector 0.7/0.8/0.6/0.5/0.5–0.65 — near-zero heterogeneity across distinct participants). [INFERENCE]
This is a caution, not a method: the "stable core" is nearly identical across participants, i.e., the disposition layer
is doing little individuation work. Nothing transfers to M15 import or M2 initial conditions.

**5. Calibration/validation.** [PAPER] Alignment is scored against **held-out human behavioral summaries** (choice
rates, rating means, SDs, condition gaps, orderings) via `s_m = clip(1 − |a_m − h_m|/B_m)`, with B_m = 1 (proportions),
2 (proportion differences), 10 (rating scales), 100 (percentages) (§5.1, App. D); family-level scores are **unweighted
means so "high-volume blocks of cells" don't dominate** (§5.1). SPIN wins Avg. on all 4 backbones (0.846/0.875/0.869/
0.821; best baseline 0.770 on DeepSeek V3.2), 40/40 paired differences positive (Table 1, §5.2, App. E). Ablations
(Table 2): freeform-intermediate lowers Avg. on every backbone, worst on Shafir–Tversky (0.089–0.152). [INFERENCE]
EPModel has no human targets, so the *metric* doesn't transfer; what transfers is the discipline (held-out outcomes;
separating marginal/contrast/ordering components; unweighted family aggregation). The held-out-outcomes rule is already
EPModel's M11.D.12 + M11.F.9.

**6. Failure modes / limitations.** [PAPER] (i) LLMs "compress human variability, miscalibrate effect magnitudes";
(ii) "Individual responses can also drift from the assigned personas"; (iii) "part of its advantage may reflect better
decomposition, format control, or compute allocation rather than the CAPS-inspired schema alone"; (iv) vocabulary/
stability sensitivity left unexamined; (v) "not a validated psychological measurement model." [INFERENCE] (iii)–(v) are
the load-bearing cautions: a structured intermediate can look like a mechanism when it is only extra compute, and the
schema itself was never sensitivity-tested.

**7. Software engineering / counterfactual tooling.** [PAPER] Strict JSON schemas per stage with clipping to [0,1];
stage output "finalized before the next stage begins" for traceability; protocol fields separated from reference-
outcome fields "to prevent outcome leakage"; the backbone-paired robustness check reports the paired difference, CI,
one-sided t-test, **and the exact sign test with its minimum attainable p-value** (1/16 = 0.0625 at n=4), explicitly
flagging "low power and fragile normality" and using it "only as a model-level robustness diagnostic, not as the
primary evidence" (App. E, Table 4). [INFERENCE] The sign-test-min-p discipline and the diagnostic-vs-primary labelling
are quotable reporting rules; the rest is already covered by EPModel's M16.A.3, M11.D.12, M11.4e/M17.A.3.

**8. Small-N / emotion / family / long-horizon.** [PAPER] None — no families, no emotional conservation, no long-
horizon dynamics. The only small-N content is the n=4 backbone paired test (App. E). [INFERENCE] The n=4 sign-test
reporting is the single small-N lesson.

**Not transferable / cautions.** (1) SPIN's "DECIDE sees only the state, not the core" restriction must **not** be
imported: EPModel's policy legitimately reads `basic_level` (M4.D.1a mixing weight) and beliefs (M4.B.2); SPIN's
restriction is an LLM anti-drift device, not a theoretical requirement. (2) The alignment metric (fitted to human
summary statistics) is exactly the kind of data-fitting EPModel forbids (M11.F.9); only its *structure* transfers. (3)
Non-peer-reviewed preprint, two study families, four backbones, temperature 1.0; §I.1 disclaims psychological validity.
(4) The near-identical trait cores across participants (App. F) suggest the "disposition" layer individuates little —
worth remembering before citing SPIN as evidence that a disposition layer *necessarily* carries identity.

### SP1 — Complexity-matched / schema-stripping mutant

**Proposed requirement.** Where a mechanism's contribution is asserted through a *structured intermediate* (the `M4.C.1`
appraisal state, the `M9` belief store, the `M5` repertoire), the mutation suite **MUST** include a complexity-matched
mutant that replaces the structured intermediate with an unstructured placeholder of equal cardinality and cost, and the
`M11.C` criteria that credit the mechanism **MUST** go red on it. A directional result **MUST** be attributable to the
*structure* the theory specifies, not to the presence of an extra processing stage.

**Where it would live.** M11 (acceptance tests / mutation record), with the mutant class registered in M10's mutation
record.

**Evidence.** §5.3 + Table 2 — `SPIN_freeform_intermediate` replaces the fixed trait/state schema with unconstrained
natural-language reasoning and lowers Avg. on every backbone (worst 0.089–0.152 on Shafir–Tversky); §I.1 concedes "part
of its advantage may reflect better decomposition, format control, or compute allocation rather than the CAPS-inspired
schema alone." Strength: ARGUED (shown on SPIN's own pipeline; the EPModel mutant form is inference).

**What it changes.** Adds a test (a new mutant class). Inference validity — keeps a directional result from being an
artefact of added machinery rather than of the specified structure. Adjacent to C22 (matched-magnitude contingency-
severing) but distinct: this keeps *compute* while stripping the *internal schema*.

**Cost/risk.** Low — one mutant per structured mechanism in the existing suite. No conflict with M3.D.4/D.5 (mutants
remain deterministic), M3.D.6, M11.F.9, or M16.B (test-side only).

### SP2 — State-bypass collapse signature (the state layer must be in the causal path and condition-sensitive)

**Proposed requirement.** A mutant that routes move selection past the appraisal state — fixing `acute_anxiety` (or the
`M4.C.1` deviation) at a constant, or selecting from `basic_level` alone — **MUST** produce a declared signature: the
selected move becomes statistically independent of the delivered event's content and the tie's state, collapsing toward
the automatic channel's default move. The acceptance suite **SHOULD** assert this signature so a state layer that does
no work is caught as an insensitive policy rather than passing as a plausible run.

**Where it would live.** M11 (mutation-shape check) + M17.B.6 (which already regresses selected moves on inputs; this
names the expected failure).

**Evidence.** §5.4 + Fig. 2 + App. E.1 — removing state elicitation makes the model "approach a near-uniform
high-response policy" while the full pipeline "produces more moderated behavior generally closer to the human target."
Strength: SHOWN in the paper; the EPModel translation is INFERENCE.

**What it changes.** Adds a test / sharpens M17.B.6 with a named expected-failure signature. Theory fidelity (state
layer is load-bearing and condition-sensitive) and inference validity.

**Cost/risk.** Low — a named mutant plus an assertion over existing log fields. No conflict with M3.D.4/D.5, M3.D.6,
M11.F.9, or M16.B.

### SP3 — Tiny-N paired check: state the minimum attainable p-value and label it diagnostic

**Proposed requirement.** Where a paired comparison rests on a tiny number of paired units (backbones, or a seed floor),
the report **MUST** state the exact sign test's minimum attainable p-value for that count and **MUST** label the
comparison a robustness diagnostic rather than primary evidence; a t-test on fewer than ~10 paired units **MUST** carry
that statement because its normality approximation is fragile and its power low.

**Where it would live.** M17 (Phase E reporting), beside M17.A.3 / M11.4e.

**Evidence.** App. E + Table 4 — "the exact one-sided sign test has a minimum possible p-value of 1/16 = 0.0625 when
all four differences are positive. We therefore use this check only as a model-level robustness diagnostic, not as the
primary evidence." Strength: ARGUED (the paper's own reporting discipline).

**What it changes.** Adds a reporting rule. Inference validity — prevents a tiny-N paired check being read as primary
evidence.

**Cost/risk.** Negligible (a reporting sentence). No conflict. **Partly covered:** M11.4e (rank-based paired statistic,
multiplicity declared), M17.A.3 (paired statistic only), and the SWEEP reports already record exact sign-test p-values
openly. The specific additions are the *minimum-attainable-p* statement and the *diagnostic-not-primary* label.

**Already covered (not written up).** Disposition/state separation (M1.A.7/M1.A.7a, M4.C/M4.D); stagewise input
restrictions (M4.B.2, M9.8, M16.A.3a); selection-rationale logging (M16.A.3); per-channel repertoire entropy (M16.A.9);
move-transition + JSD readouts (M17.B.5); ordinal/monotone orderings (M11.C.38, M11.C.41); outcome leakage / held-out
targets (M11.D.12, M11.F.9); paired sign tests with multiplicity (M11.4e, M17.A.3, C25).

# Part 4: Socio-Foundation

## Reader report: Wang, Xie, Mou, Luo & Wei, "Socio-Foundation: A Model for Generalizable Individual Behavior Simulation via Hierarchical Capability Distillation", arXiv 2610.08967v1

An LLM post-training paper (Qwen3-8B base) for simulating *individual* behaviour across social contexts. No families, no
triads, no conserved emotional quantities, no multi-decade horizon. What transfers is narrow: a handful of
evaluation-reporting disciplines in §E and §D.3.

**1. Simulation formalism.** [PAPER] §3: individual simulation is formulated as *conditional generation* over
multi-party episodes — response `(z, y)` with `z = (persona, history, context)`, target `p*(y|z)` approximated
autoregressively (Eq. 1). There is no tick clock, no event queue, no conserved state, no synchronous/asynchronous update
question — it is turn-level text generation. [INFERENCE] Nothing in the formalism transfers to a rule-based engine.

**2. Agent architecture.** [PAPER] §1, §3: policy `πθ` conditions on persona `p`, interaction history `h`, social context
`c`. The named failure is **persona flattening**: preference optimisation "favors responses that align with the dominant
preference distribution", driving "behavioral homogeneity". §5.2: general-purpose models "drift back into the assistant
role". Decoupling specialization from integration via a 3-stage hierarchy (DAPO task experts → off-policy capability
experts → multi-teacher on-policy distillation, §4.2–4.4). [INFERENCE] Confirms `M3.D.6` and the design-lessons §3.2
homogenization findings; adds nothing to the v2 rule-based policy.

**3. Interaction/network structure.** [PAPER] §4.1 defines **Social Grounding (S)** as "reasoning about beliefs,
intentions, and emotions while respecting knowledge boundaries and private information"; §D.2 metric "Private acc."
scores handling of secrets/private information. No dyads, ties, thresholds, cascades or information-distortion-through-
routing. [INFERENCE] The knowledge-boundary/private-information concept is **already covered** in EPModel by `M4.B.2`,
`M9.8`, `M1.F.1b`, and held item SV2.

**4. Initialization.** [PAPER] §4.1: capability taxonomy is "theory-guided" by McAdams & Pals' New Big Five; §C.2 fixes
training seed 42, temperature 0 in eval, LoRA rank 32. [INFERENCE] Persona/context conditioning, not initial-state-as-
distribution; nothing transfers to `M17.C.1`'s `D0`.

**5. Calibration and validation.** [PAPER] §5.1–5.4: IndiEval = 29 metrics, 13 benchmarks, 11 targets, 6,297 cases
(+165 = 6,462); main result Avg 61.7 vs Qwen3-8B 50.7 (+11.0), gains on 24/29 metrics; best/second-best on 86% of
metrics vs 8B specialists (Table 1). Ablations (Table 2); removing the **N** expert causes the largest drop, Avg
61.69→59.24 (Table 3). OOD: Mistakes 57.00, HiToM 62.00, τ-USI 69.31 (Fig. 6). **§E (Repeated-Evaluation Stability)**
is the transferable core: a fixed checkpoint run R=5 times with checkpoint/seed(20260824)/prompts/cases/scoring held
fixed and temperature 0; reports **mean ± SD, min, max, range** (Table 11: LifeChoices accuracy 79.800 ± 0.583, range
1.600; HUMANUAL response alignment 12.486 ± 0.585; MirrorBench GTEval 54.425 ± 0.396; PI 62.517 ± 1.690; RNR 76.250 ±
1.723). A **fixed-reference control** (human-reference RNR scored 5×: 90.0, 92.0, 90.0, 90.5, 91.0 → mean 90.700 ±
0.837) isolates scoring-pathway variance. [PAPER] §E.3 disclaimers: "the observed run range is not a significance
threshold"; assessing differences "requires matched comparison". **What they could NOT do:** no cross-training-seed
ensemble, no sensitivity analysis over hyperparameters, no small-N/family validation.

**6. Failure modes / limitations.** [PAPER] Persona flattening and assistant bias; specialized models "reported scores
falling to zero" outside their task family; cross-task "objective interference" when pooling corpora; evaluation
stability is **metric-dependent** even within one benchmark — GTEval SD 0.396% vs PI 1.690%, RNR 1.723% (§E.3). [PAPER]
§E.3 caveat: the fixed-reference control's variance "cannot simply be subtracted" from the main variance because control
and generated-dialogue scores evaluate different inputs.

**7. Software engineering.** [PAPER] Hierarchical decoupling of specialization from integration (§4.2–4.4); frozen-
checkpoint repeated-eval protocol with a held eval seed (§E.2); LLM-judge rubrics; data cleaning with retained/removed/
transformed counts (Table 7: 19,678,715 in → 19,018,645 kept, 660,070 removed, 52,615 transformed); fixed protocol
bounds for score normalization (D.3). [INFERENCE] The most transferable single practice is §E's error-reporting
convention (below, SF1).

**8. Small-N / emotion / family / stress / long-horizon.** [PAPER] None. Emotion appears only as taxonomy labels A15
"emotion and situation understanding", A18 "context-appropriate emotional responses" (Table 4); no emotion-as-state, no
family/household unit, no stress dynamics, no multi-year horizon. [INFERENCE] No transfer.

**Not transferable / cautions.** This is an LLM post-training + benchmark paper; its mechanisms (distillation, RL) are
orthogonal to a Bowen consistency engine. Its ablation "removing an expert lowers Avg" is not a mechanism-level
counterfactual and must not be cited as one. The §E variance study is the sole strong transfer, and even it describes
an *evaluation* pipeline, not a model; EPModel's readouts are deterministic functions of state, so the "judge variance"
component it isolates has no direct EPModel counterpart — only its reporting *conventions* transfer.

### SF1 — Ensemble dispersion must be reported as a standard deviation, with observed extrema, and never read as significance

**Proposed requirement.** Every Phase E ensemble report **MUST** state the error term on a per-seed quantity as a
**standard deviation across seeds** — **never** a standard error or confidence interval — and **MUST** report the
observed **minimum, maximum and range** of the per-seed values alongside the mean ± SD. The report **MUST** state that
the observed range is **not** a significance threshold and that whether a direction holds rests on the paired per-seed
statistic (`M17.A.3`) with its declared margin (`M17.A.4`), not on the spread.

**Where it would live.** Phase E: ensemble runner / reporting (`M17`), next to `M17.A.1`–`M17.A.4`.

**Evidence.** §E.2 (Eq. 7; "Error terms denote standard deviations across run-level scores, **not standard errors or
confidence intervals**") and §E.3/Table 11, which report Mean ± SD, Min., Max., Range over R=5 runs. §E.3: "the
observed run range is not a significance threshold". Strength: **SHOWN** (the paper practises and states it).

**What it changes.** Adds a reporting rule; **inference validity**. Prevents two silent errors — conflating a run-level
SD with a standard error/CI (which misstates precision), and reading an observed min–max spread as evidence of
significance. No mechanism change.

**Cost/risk.** Trivial (a reporting convention outside the engine). No conflict with `M3.D.4`/`M3.D.5`, `M3.D.6`,
`M11.F.9`, or `M16.B`. One interaction to state explicitly so it does not read as a contradiction: `M17.A.1` uses a
confidence-interval *half-width* as a **stopping rule** for seed count; SF1 forbids reporting that CI *as* the error
term. The two coexist (CI to decide when to stop; SD + extrema as the reported dispersion), but the distinction
**SHOULD** be stated in `M17` so `M17.A.1`'s CI is not re-reported as an error bar.

### SF2 — Readout normalization bounds are fixed and declared, never observed

**Proposed requirement.** Any normalization of a readout (repertoire entropy `M16.A.9`, symptom/functional levels,
dispersion summaries) **MUST** use bounds **declared in `M10`/config** (or the readout's theoretical range), and **MUST
NOT** use bounds computed from the observed ensemble. A report that normalized by observed min/max **MUST** be flagged
as such.

**Where it would live.** `M10` (parameters/config) with the readout definitions in `M16`/`M17`.

**Evidence.** §D.3: "Bounds are independent of the observed model scores"; §E.2: "The bounds are specified by the
scoring protocol, not estimated from these five runs." Strength: **ARGUED** (stated as practice; the why-it-matters is
INFERENCE).

**What it changes.** Adds a reporting/config rule; **inference validity**. Normalizing a dispersion or diversity readout
by its own observed range collapses or inflates the reported spread and makes two arms' dispersions incomparable; fixed
bounds keep the denominator a constant of the protocol, not a function of the run.

**Cost/risk.** Trivial (one convention on readout definitions). No conflict with determinism, no-LLM, no-fitting, or
engine purity — it constrains reporting/config, not decision logic.

**Already covered (not written up).** Social Grounding "knowledge boundaries / private information" → `M4.B.2`, `M9.8`,
`M1.F.1b`, held item SV2; persona flattening / homogenization → `M3.D.6` and design-lessons §3.2; "assessing a
difference requires matched comparison" → `M17.A.3`; "report the distribution, not a mean" → `M17.B.4`; fixed-reference/
no-interaction control family → `C34`.

# Part 5: Prompts versus Rules

## Reader report: Wang, Khasanova, Saini, Konnelly, Kavehzadeh, Lee & Attia (Dialpad), "Prompts versus Rules: Auditing and Controlling Speech Naturalness Behaviors in Voice User Simulators", arXiv 2610.11015v1

**1. Simulation formalism / scheduling** [PAPER] — The rule-based engine is **event-driven**, not polled: decisions
fire at mid-speech "short pause" boundaries (200 ms) and turn-end silence (500 ms), detected by a VAD (§3.1, Fig. 2).
τ-Voice by contrast polls a "fixed 2.0-second tick schedule" invoking an LLM every 10 ticks (§2, §5.2). [INFERENCE]
This is a threshold-gated activation instance; nothing new for EPModel beyond what `M17.E.6` (alternative activation
regime) already covers. — **Text-seeded determinism**: the disfluency RNG is "seeded directly from the utterance text
(seed = text)", so replaying the same LLM response gives identical placement, "enabling reproducible benchmark runs"
(§3.2, Fig. 1). [INFERENCE] Same family as C1 (keyed draws); not new.

**2. Agent architecture / decision rule** [PAPER] — Rule-based controls are governed by tendency parameters α, β, γ ∈
[0,1], "At 0.0, the behavior is disabled" (§3.2). Interruption uses a patience threshold (`10.0 − 8.5×β` seconds) plus
word/type gates; backchanneling a cadence threshold (`25 − 17×γ` words). The interruption rule "is evaluated first and
returns immediately", so when it passes the backchannel rule is never reached (§3.2, Fig. 2). [INFERENCE] EPModel
resolves one outcome per tick by softmax over propensity, not priority-ordered rules, so the priority-ordering lesson
does not transfer; the "disabled at zero" shape is already `M10.C.4a`'s ablation form.

**3. Interaction / opportunity structure** [PAPER] — The one transferable mechanism note: an executed interruption
"forcibly terminates the ongoing agent turn, thereby eliminating subsequent mid-speech pauses" — total opportunities
contract from 230 (β=0) to 194 (β=1.0), a "shrinking denominator" they judge weak (§5.2). [INFERENCE] An act changing
its own opportunity set downstream is a real, subtle readout trap: per-tick and per-opportunity rates can move in
opposite directions.

**4. Initialization / frozen evaluation set** [PAPER] — From 131 conversations they extracted 858 response positions,
sampled 300, dropped one, and "all conditions are computed over the same 299 paired positions with identical system
contexts" (§4). [INFERENCE] Identical-context pairing across conditions is the same discipline EPModel already holds;
nothing new.

**5. Calibration / validation** [PAPER] — Realized rates reported **per opportunity and per agent turn** (two
denominators), not just raw counts (Table 2). Rates audited against the configured setting (Abstract, §6). Statistics:
two-sided Wilcoxon signed-rank on per-scenario counts (all p < 10⁻³, W = 0 throughout), 1000-iteration paired bootstrap
CIs, Kendall τb trend tests (Table 5, 6; App. E). Honest caveat: monotonicity "is reported as observed rather than
tested" because "no test compares adjacent settings" (App. E). [INFERENCE] This is the exact gap `M17.E.2(b)` asserts on
but does not currently *test*; see PR2.

**6. Failure modes / negative results (LLM prompting)** [PAPER] — Prompting **underdelivers** (fillers/1k at "most
sentences": 34.72 4o-mini, 73.67 gpt-5, 75.28 Gemini vs 83.78 injected at α=1.00), **saturates** (roughly-half → most-
sentences nearly plateaus), **front-loads** (turn-initial fillers 62.8–67.3% on 4o-mini, 71.9% under the τ-Voice
prompt, vs 11.1–15.6% injected), and **fails** repetitions (2.96 vs 47.06/1k) and self-initiated repairs entirely (§5.1,
Table 1). — **Inter-model variance**: identical prompts yield filler rates differing "by a factor of 1.92× to 2.27×" —
"prompt instructions are not portable rate settings" (§5.1). — **Under-dispersion**: prompted variance-to-mean 0.6–1.0
(unnaturally uniform) vs injection 1.15–1.29 and the human over-dispersed regime (§5.1, Table 4). — **One-sided
persona**: τ-Voice produced 0.633 interruptions/turn (219/346) but 0.038 backchannels/turn (13 of 1,277 consultations),
plus 1,277 billed classifier calls delivering almost no effect (§5.2). [INFERENCE] All of this is direct new evidence
for `M3.D.6` and the audit-rather-than-configure principle. It adds numbers, not a requirement.

**7. Software engineering** [PAPER] — Headline: "auditing and reporting realized naturalness behaviors, rather than
configured settings, is what makes that gap visible" (Abstract). Alphanumeric protection: disfluency injection excludes
word boundaries around emails/phones so it cannot corrupt downstream entity-extraction or WER references (§3.2).
[INFERENCE] A mechanism must not corrupt a quantity another readout depends on — the same instinct as EPModel's readout
traps. Acknowledged limitation: β and γ were varied **one at a time** because the priority rule pre-empts backchanneling
— the interaction is unmeasured (Limitations). [INFERENCE] A caution for one-at-a-time ablation (`M10.C.4a`).
Contradiction ablation: τ-Voice's prompt prescribes fillers while also demanding "MINIMAL VERBOSITY: Avoid filler
words"; dropping the conflicting line moved rates only 0.94–1.22×, so "the instruction itself, not the conflicting line,
sets the delivered rate" (App. A). [INFERENCE] The remove-the-suspect-cause-and-measure pattern is already EPModel's
mutation discipline.

**8. Small-N / emotional / family / long-horizon** [PAPER] — None. Two-party single-call telephony dialogue, no family,
no triads, no conserved emotional quantities, no longitudinal dynamics beyond a single call.

**Not transferable / cautions:** the speech-naturalness metrics (filler rate, turn-initial share, pause thresholds) are
domain-specific and do not carry. The priority-ordered decision rule does not carry (EPModel is softmax). The paper's
own caveat cuts both ways: "controllability is not the same as realism" — a rule-based engine buys controllability and
auditability, not realism, which still rests entirely on the Bowen-informed rules themselves. Single fixed target agent,
three models, one architecture; effects "may not hold under significantly different conditions" (Limitations).

### PR1 — Realized move rates are reported against the opportunity denominator, not only per tick

**Proposed requirement.** For every `M5` move whose legality is conditional (`M4.D.1e`'s legal set — `CUTOFF`,
`TRIANGLE`, `I-POSITION`, `PURSUE`), the run log `M16` **SHOULD** report the realized rate on **two** denominators: per
fast tick, and per opportunity (a tick on which the move sat in the person's legal set, already logged by `M16.A.3b`).
A readout or criterion that asserts a "rate" (`M11.C.45` is the first) **MUST** state which denominator it uses, and a
per-tick rate that diverges in sign from the per-opportunity rate **MUST** be flagged rather than reported as one number.

**Where it would live.** M16 run log (readout column beside `M16.A.9`); the naming obligation on `M11` criteria.

**Evidence.** §4 and §5.2/Table 2 — the paper reports interruption/backchannel rates both "per opportunity and per
agent turn," and demonstrates the denominator is endogenous (opportunities contract 230→194 at β=1.0 because firing
truncates the turn). Strength: SHOWN (as a measurement), transfer INFERENCE.

**What it changes.** Adds a reporting rule + a test obligation. Inference validity: it separates "the move is rare
because it is rarely legal" from "the move is rare because the policy avoids it even when legal," which a raw per-tick
rate conflates.

**Cost/risk.** Low — the legal-set mask already exists (`M4.D.1e`, `M16.A.3b`), so the opportunity count is a pure-
observer computation over existing state; consistent with `M16.B`. No conflict with determinism, `M3.D.6`, `M11.F.9`,
or engine purity.

### PR2 — Monotonicity is asserted by adjacent-setting tests and reports its tie fraction, not by inspection

**Proposed requirement.** Where `M17.E.2` (or `C16`) reports a dose–response curve as monotone, the report **MUST**
include, for each adjacent pair of swept settings, the fraction of seeds whose trajectory is identical across the pair
(the tie fraction), and monotonicity **MUST** be judged on adjacent-pair differences, not on the end-to-end trend alone.
A mechanism that is monotone by construction but whose trend statistic is deflated by ties **MUST NOT** be reported as
non-monotone.

**Where it would live.** M17.E.2 (Phase E dose–response), as a clause on its monotonicity property (b).

**Evidence.** App. E — "no test compares adjacent settings, so monotonicity… is reported as observed rather than
tested"; and "Injection's τb is the lowest of the four despite being monotone by construction, because ties dominate:
the generator is seeded per utterance… 43% of positions are identical at all four" (τb = 0.275 vs 0.520–0.599 for the
prompted models, Table 6). Strength: SHOWN.

**What it changes.** Adds a test rule and a reporting rule. Inference validity: in a deterministic-per-seed engine,
adjacent `[I]` constant settings produce identical trajectories for many seeds, so a weak trend statistic is expected
for a *correct* monotone mechanism. This prevents a false "non-monotone → functional-form bug" flag (the `M17.E.2(b)`
escalation) being fired on ties.

**Cost/risk.** Low — the tie fraction is computable from per-seed trajectories already run. No conflict with
`M3.D.4/D.5` (it exploits determinism), `M11.F.9`, or engine purity.

### PR3 — Non-linearity of configured→realized mapping is bound to the endogenous input distribution; it is not automatically a functional-form finding

**Proposed requirement.** When a dose–response curve over an `[I]` constant is non-monotone or non-linear, the
`M17.E.2(b)` report **MUST** state the distribution of the input quantity the constant gates (the values actually
encountered over the run, from `M16.A.10`'s margins), and **MUST NOT** flag the shape as a functional-form error unless
the non-linearity persists after accounting for that distribution. Non-linearity attributable to the threshold
interacting with an endogenous, shifting input distribution **MUST** be reported as expected, not as a defect.

**Where it would live.** M17.E.2(b), as a qualification on the monotonicity flag.

**Evidence.** §5.2/§6 — "the mapping from a configured parameter setting to realized behavior is non-linear… because
deterministic patience and cadence thresholds interact dynamically with the acoustic speech distribution of the target
agent"; and "Parameter scaling changes the potential decision points in time… rather than simply multiplying event
output." Strength: SHOWN (they observe it and name the cause); transfer INFERENCE.

**What it changes.** Adds a reporting rule; inference validity. It prevents a dose–response sweep from misattributing
threshold–distribution interaction to a bug in the functional form, which is the single most likely false alarm for
EPModel's anxiety- and load-dependent thresholds (`M4.C`, `M5.C`, `M7`), whose operating distributions are themselves
endogenous.

**Cost/risk.** Low — reads `M16.A.10` margins that are already logged. No conflict with determinism or engine purity;
consistent with `M17.E.3`'s invariance-interval reading.

### PR4 — A dispersion (clustering) readout on the event stream, to catch artificial uniformity

**Proposed requirement.** The run log `M16` **SHOULD** carry, per agent and per window, the index of dispersion
(variance-to-mean ratio) of move counts and of delivered-event counts, computed over the fast ticks in the window. It is
a description of temporal clustering and **MUST** be labelled as such — a value near or below 1.0 flags a stream that is
smoother than a clustered emotional process, and is a uniformity artefact to investigate, not a target to hit.

**Where it would live.** M16 run log (readout alongside `M16.A.9`).

**Evidence.** §5.1/Table 4 — prompted output is under-dispersed (V/M 0.6–1.0, "unnatural uniformity across turns")
while rule-based injection and natural speech are over-dispersed (1.15–1.29 and >1.0). Strength: SHOWN (as a metric that
separates natural from artificial output); transfer INFERENCE.

**What it changes.** Adds a readout; inference validity. Bowen's account is of anxiety that runs in cycles and crises
that cluster, so an engine whose clocks deliver an even trickle of events would be a scheduler artefact — this readout
is the cheap way to notice it.

**Cost/risk.** Low — pure-observer over the existing `M4.E.1` event stream, consistent with `M16.B`. It is `[I]`-grade
description with no target value, so it conflicts with nothing; the only risk is over-reading a description as a goal,
which the labelling clause forbids.

**Already covered (not written up).** "Audit realized, not configured" → `M16.A.3`, `M16.A.8`, `M16.A.9`/`M11.C.16`/
`M11.C.40`. Text-seeded determinism → C1 (keyed draws). Contradiction ablation → existing mutation discipline. The LLM
failure numbers (saturation, non-portable settings, one-sided profile) support `M3.D.6` without adding a requirement.

# Part 6: Latent Identity Reversion

## Reader report: Fraile Navarro, "The Persona Is Still There, but Who Is Speaking? Latent Identity Reversion in Persistent AI Agents", arXiv 2610.01490v1

**1. State representation / formalism** — [PAPER] The decisive state is whether the persona is re-injected at
system-prompt level each turn, not what is in conversational history: turn 1 carried a 44,654-character system prompt,
turn 2 27,478 characters, "with the 21-message conversational history intact" (§3). "The persona evaporates; the memory
of having been the persona remains." [INFERENCE] Scaffold/session state is part of the agent's behavioural state; the
visible transcript underspecifies it. This is the LLM-line analogue of C6/Li & Tao (scheduler + visibility object are
model content) and M16.A.1a's component-identity logging.

**2. Agent architecture (memory)** — [PAPER] Conversational representation ≠ enactment: persona information sitting in
history did not keep the persona in the "I" role (§3, §5). "identity was implemented as an initial setting rather than
a persistent property" (§5). [PAPER] Reversion target was the model's trained default — "I'm Claude, an AI assistant" —
the "default-assistant attractor" of Lu et al. (§5). [INFERENCE] Continuity cannot be carried by conversation memory
alone; a privileged per-turn anchor is load-bearing.

**3. Interaction/network** — none. Single agent + one user; no multi-agent topology.

**4. Initialization** — [PAPER] The whole experiment is an initialization manipulation (anchor injected once at
session-create vs every turn). Unanchored: ≥1 failure in 37/40 sessions; anchored 0/20 (Fisher p = 4.2×10⁻¹³; Table 2,
§4). [PAPER] Anchor loss = vulnerability, not deterministic loss: persona-rich human exchange before the unanchored
turn → 0/20 dissociations (E1); a single heartbeat turn → 10/10 any-failure (§4). [PAPER] Reversibility: restoring the
anchor rescued 10/10 (5/5 within-conversation) (E2, §4). [INFERENCE] Initial-condition sensitivity in purest form: one
binary scaffold flag, not cumulative exposure, flips the outcome.

**5. Calibration / validation** — [PAPER] Prospectively specified, version-controlled protocol; falsified predictions
retained; timestamped addenda (§3). [PAPER] Blind LLM judge cross-validated by blind humans: κ = 0.93 (channel
recognition), κ = 0.80 (identity dissociation) (§3). [PAPER] Codebook instability: prespecified v1 gave anchored
proportions 6/17–17/17 across three coders; v2 collapsed both arms to 0 (p=1); direction-aware v3 gave identical
classifications from all three (Fig. 5). [PAPER] Limitations: one model family, one harness; E1 confounds interaction
type with content richness; scheduled turns compressed in time; self-ID probes do not establish subjective experience
(§5).

**6. Failure modes / negative results** — [PAPER] Heartbeat repetition alone did not reproduce the incident: 0/46
anchored failures including verbatim replay (§4) — echo-chamber hypothesis falsified. [PAPER] Dissociation rate flat
across N = 1,3,7,15 (ρ = −0.13, n.s.); N changed expression only — bare-token collapse 5/10→0/10 (ρ = −0.46, p≈0.003)
(§4). [PAPER] Silent reversion: removing the name cue gave 0/10 overt dissociation but 10/10 harness self-identification
in direct probes (E4, §4). [PAPER] Behavioural recovery unreliable: 13/37 (35%, 95% CI 22–51%); persona enactment 1/18
recovered vs 17/17 anchored (p = 4.2×10⁻⁹) (E3-R, §4). [PAPER] 9/37 dissociated replies would have been silently
dropped in production; 19/28 delivered had the revealing HEARTBEAT_OK token stripped (§5).

**7. Software engineering** — [PAPER] Root cause: harness resume bug (persona block passed on session-start command
only), verified via logging proxy; fixed by making per-turn re-injection the default (§3, §5). Same failure
independently reported three months later. [PAPER] Replication code, pre-registration, raw sessions, blind-coding
materials released ("identity-as-a-launch-flag") (§5).

**8. Small-N / long-horizon** — [PAPER] Future work names realistic long-horizon agents "where human conversations,
autonomous tasks and scheduled interactions accumulate over days or months" as untested (§5).

**Not transferable / cautions.** Single model family + single harness + one naturally-occurring failure; no multi-agent
or family dynamics; the manipulation is about prompt scaffolding, not emotional process. The core rule-based engine is
untouched (no LLM in the decision path, M3.D.6). The core-engine analogue of "behavioural continuity ≠ state
continuity" is already covered (M5.F counterfeit act identity; M17.F.2 settling condition). All transfer is confined to
the exploratory LLM/narrator line.

### IR1 — Per-turn system-level persona re-anchoring (narrator/LLM line)

**Proposed requirement.** In the exploratory LLM-agent line (and any Phase F narrator speaking first-person as a family
member), the persona/identity block MUST be re-injected at the privileged system-prompt level on every turn or call, and
MUST NOT rely on conversational history or a session-start-only injection to carry the identity. A run whose harness
drops the block on resumed turns MUST be treated as an unanchored arm, not silently as a continuation.

**Where it would live.** Exploratory narrator/LLM line (Phase F), a protocol item alongside X1–X4 in the candidates
file; does not touch the core engine and MUST NOT relax M3.D.6.

**Evidence.** §4, Table 2 — anchored 0/20 vs unanchored 37/40 (p = 4.2×10⁻¹³); §3 (launch-flag mechanism); §5 (fix was
per-turn re-injection default). SHOWN.

**What it changes.** Adds a mechanism requirement (re-anchoring) that preserves persona continuity over long horizons —
inference validity for the exploratory line. Distinct from X10 (a one-time pre-use persona check), because the paper
shows a one-time injection silently expires on turn 2.

**Cost/risk.** Trivial (one prompt block per call). No conflict with determinism M3.D.4/.5, no-fitting M11.F.9,
constants, or engine purity M16.B — it is outside the engine. If the narrator path is deterministic-only (SEAA §7.6
verbalizer), this requirement is vacuous for that path and MUST say so.

### IR2 — Represented-vs-enacted identity probe; behavioural recovery ≠ identity recovery (narrator/LLM line)

**Proposed requirement.** Any LLM-line readout reporting an agent as "recovered," "normal," or "unchanged" MUST be
backed by a direct, non-leading identity probe (e.g. "who am I talking to right now?"), blind-coded with a
direction-aware taxonomy (which identity occupies the first-person role), and MUST report behavioural recovery and
identity recovery as separate quantities. A readout that infers identity continuity from surface behaviour alone MUST be
reported as insufficient.

**Where it would live.** Exploratory narrator/LLM-line readout (Phase F), protocol item alongside X1–X4.

**Evidence.** §4, E4 (0/10 overt vs 10/10 harness self-ID) and E3-R (1/18 vs 17/17, p = 4.2×10⁻⁹); Fig. 5 (codebook
evolution to direction-aware coding); §3 (κ = 0.80 identity, 0.93 channel). SHOWN.

**What it changes.** Adds a detection/readout rule that stops a silent reversion from being reported as a clean run —
inference validity for the exploratory line.

**Cost/risk.** Low (one probe turn + blind coding); outside the engine, so no conflict with determinism/purity. The
direction-aware taxonomy was a post-hoc secondary analysis in the paper — adopt it pre-specified where possible.

### IR3 — Harness/scaffold state is behavioural state; log it (narrator/LLM line)

**Proposed requirement.** In the exploratory line, the per-turn presence of the persona anchor (and the harness's
session-resume behaviour/version) SHOULD be recorded in the run record, because behaviour depends on hidden scaffolding
state absent from the visible transcript.

**Where it would live.** Exploratory-line run record (the analogue of M16.A.1a for the core engine).

**Evidence.** §5 — infrastructure choices "treated as part of the agent's behavioural state, rather than as
implementation details"; §3 (logging-proxy verification). ARGUED.

**What it changes.** Adds a reporting rule making silent reversion auditable after the fact — inference validity.

**Cost/risk.** Trivial. The core-engine analogue is already covered by M16.A.1a (component identity + version); this is
the LLM-line extension only.

**Already covered (one line each).** "Behavioural continuity ≠ state continuity" for the core engine → M5.F and
M17.F.2, no new requirement. LLM-judge with blind-human κ validation → DESIGN_LESSONS §3.4 already forbids LLM-only
scoring; the paper's κ = 0.80–0.93 is an instance, not a change.
