### 6.1 The standard each entry is drafted against

- **done.** An existing test in the default suite asserts the behaviour the ID requires, so that removing or
  reversing that behaviour would make the test fail. A test that only runs the code, or asserts a neighbouring
  property, does not count. Where the ID has several requirements (several MUSTs), each needs a test, or the entry is
  *partial* and names the one not covered. The note says which test covers which requirement and why.
- **done through a criterion.** An ID whose behaviour is an outcome an `M11.C` criterion checks (for example
  `M7.E.1`'s ordering, a result since revision 11) is *done* only if that criterion's row on the page is *done*;
  otherwise *partial*, quoting the criterion's status. A criterion test is ensemble-marked and outside the default
  suite, so its existence proves nothing by itself (B1.4).
- **partial, "built, no test".** The code exists — the note names the file and function — and no test asserts the
  behaviour. Where some requirements are tested and some are not, *partial* says which.
- **not done.** Not built, with the reason: the spec marks it for a later phase (`M9.5` carries `→E`), or no code
  implements it (the note says where it was searched for).
- **states no behaviour a test can check.** A definition (`M1.A.0`, the meaning of *emotional*), a rule about the
  project's own method, or a framing prohibition with no code path. Decision 2 below.

Each entry is drafted from three readings: the requirement's full text in `docs/bowen_agent_model_spec_v2.md`; the
code that implements it, found by the ID in comments and docstrings and by the names the requirement uses; and the
tests that exercise that code. Every existing override is re-drafted under the same standard, which is how the overrides
that name Phase C or D as work to come (about 19) and those that describe a gap without saying whether it closed
(about 11, §1) are brought up to date.
