# Plan: the spec coverage page after Phase D

**Status: DRAFT for owner approval, 2026-10-19; revised 2026-10-20 after stage 1's regeneration (the numbers did not
change; Part A's timing did). Nothing built.** Written when `docs/spec_coverage.md` was found out of
date while compiling a reading list for an outside reviewer. It is generated by
`python3 tools/spec_coverage.py tools/spec_coverage_phase_b.json docs/spec_coverage.md`, and regenerating it with the
tool as it stands cannot bring it up to date. Part A changes how the tool reads what exists; Part B is a new evidence
mapping, which needs a judgment for each requirement.

## 1. Why the page is out of date

Numbers measured with the tool as it stands at `08a2f71` (version 2 stage 1, step 6), and the same at `169347e`
(step 8, after the regeneration): **575 IDs: 274 done, 70
partial, 231 not done.**

- **The header is fixed text.** `render()` writes "Spec coverage — after Phase C" and "Phases D and E build most of
  the rest", whatever has been built.
- **Criteria are read from the Phase C records only.** `ensemble_verdicts()` reads `docs/phase_c_ensemble_record.md`,
  `mutation_reds()` reads `docs/phase_c_mutation_record.md`, and `NOT_BUILT` comes from
  `src/bowen/ensemble/criteria.py` alone. So the 27 criteria absent from the Phase C record show *partial*, "built; no recorded
  ensemble verdict yet (the Phase D record is plan step 12)", although the Phase D records have existed since
  2026-10-13 and 2026-10-15. This is the `TODO.md` entry "Phase D record, review of 2026-10-13".
- **"Not done" cannot tell built from unbuilt.** An ID with no test named for it is *not done*, and its note is the
  phase from `MODULE_PHASES`. Phases C and D are finished, so a note "Phase C" or "Phase D" now reads as "not built
  yet", which is wrong for many of them. Example: `M2.2`, the twelve-person reference family, is
  `config/bowen/family_phase_d.md` and every Phase D run loads it, but no test is named for `M2.2`. Of the 231 not
  done, 167 point at Phase C or D; 21 of those 167 are mentioned by ID anywhere in `tests/` (a text search, so an upper
  bound on what is verified). The other 64 are Phase E (51), Phase F (3), prohibitions checked by review (7) and three
  with their own notes.
- **19 of the 75 hand-written overrides name Phase C or D as work still to come**, and about 11 more describe a gap
  without saying whether it has since closed. Examples: `M6.3` "open owner
  decision (disposition at death); blocks `M11.C.37` and Phase D" (decided and built at revision 28); `M6.I.5`
  "`basic_level` does not move until the Phase D estimator"; `M1.A.13` "the derivation (`M1.A.13a`) is Phase D";
  `M11.F.9` "readouts are Phase D". `M11.C.16`'s override is hand-written and says "passes" (`TODO.md`).
- **Stage 1 step 7 regenerated the page with the tool as it stands**, so `test_m141_spec_coverage_is_current` passes
  and everything above still holds. (Stage 1 step 5 moved the `M13.2` override off the retired
  `tests/test_simulator.py`.)

## 2. Part A — what the tool reads (mechanical, no new evidence judgments)

- **A1.** Read every record: the Phase C, Phase D part I and Phase D part II ensemble records and both mutation
  records, through the readers `tools/version_1_status.py` already has (`record_rows`, `red_mutants`, `not_built`,
  `proved_by_test`). The rule is unchanged: *done* only when every entry passes and each has a red mutant, or the row
  is "pass, proved by a test"; *partial* with each entry's verdict otherwise; *not done* when not built.
- **A2.** For a criterion that fails and is accepted as a finding, or is out of scope, the note quotes the owner's
  disposition from `docs/version_1_dispositions.md`. The status stays *partial* or *not done*: this page reports what
  is built and proved; the dispositions page reports the decision.
- **A3.** The header names the records read and their hashes, in place of "after Phase C".
- **A4.** For an ID with no test named for it, the note reads "no test named for it (module built in Phase …)" in place
  of the bare phase, so it cannot be read as unbuilt.
- **A5.** `M11.C.16`'s hand-written override is removed; its row comes from the record like every other criterion.
- **A6.** `docs/REVIEWER_READING_LIST.md` §3 and §8 say this page is out of date. Update both in the commit that
  regenerates the page.

Tests (each proved failing by the mutation named):
- `tests/bowen/test_spec_coverage.py::test_m141_phase_d_criteria_read_from_their_records`: a Phase D criterion's row
  carries its record's verdict. Mutation: the tool reads the Phase C record only.
- `tests/bowen/test_spec_coverage.py::test_m141_accepted_finding_shows_its_disposition`: an accepted finding's note
  carries the disposition. Mutation: the disposition is not read.
- `test_m141_spec_coverage_is_current` (existing) then covers the regenerated page.

Cost: a tool change and a regeneration that runs nothing (seconds). **When:** now, as its own change; stage 1's records
exist, so the regeneration only renders the page from them. Stage 1 step 1 edited `tools/spec_coverage.py` (S1.5d), so
Part A starts from `plan-phase-b` at or after `169347e`.

## 3. Part B — the new evidence mapping (a judgment for each ID)

The 167 IDs that point at Phase C or D, and the 75 existing overrides, each need one of: built and verified by a test
named for something else (an override citing that test, with the reason it verifies the ID); built and not verified by
any test (*partial*, "built, no test"); or not built (*not done*, with the reason). `M14.1` requires every *done* to
carry the test that proves it, and `test_m141_every_done_names_an_existing_test` enforces that the test exists.

- **B1.** Claude drafts an entry for each ID, reading the requirement, the code that implements it and the tests that
  exercise that code, into the overrides file. A *done* cites an existing test and says why it verifies the ID; where
  none does, the entry is *partial*, not *done*.
- **B2.** The owner reviews the draft as a list. Every *done* is a status claim (P6).
- **B3.** The overrides file is renamed `tools/spec_coverage_overrides.json`, since it is no longer Phase B's; the
  tool's docstring, `tests/bowen/test_spec_coverage.py` and the page's header follow.

Cost: one reading pass over about 240 entries; not measured. **When:** after Part A, so each entry is drafted
against the page Part A produces. Stage 1's tests are all in (steps 0–8).
