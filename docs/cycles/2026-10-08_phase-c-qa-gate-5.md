## Verification of the two fixes

### Finding 1 (HIGH, P6/P26) — the stale "483 tests pass" in CHANGELOG.md: FIXED

`b8fa8bb` rewrites `CHANGELOG.md:48` from "…apart from the hash they are byte-identical. **483 tests
pass**." to "…apart from the hash they are byte-identical. The suite then held 483 tests."

This resolves the guard failure by a different route than gate-4's literal suggestion (gate-4 proposed
bumping the number to 485). The reword is the more correct fix: the second-gate entry is a historical
record of a point when the suite *was* 483 tests, and bumping it to 485 would falsify that history. The
new phrasing also falls outside `test_claimed_test_count_matches_the_suite`'s pattern
(`(\d+)\s+tests\s+(?:pass|green)`), so the guard no longer flags it.

Verified two ways:
1. `grep -rniE '[0-9]+ tests (pass|green)'` across all seven `CITING_DOCS` returns exactly three hits,
   each "485 tests pass" (`CHANGELOG.md:51`, `CLAUDE.md:79`, `docs/phase_c_completion_report.md:15`).
   No other `\d+ tests pass/green` claim remains.
2. The guard test itself passes: `python3 -m pytest tests/test_spec_consistency.py::test_claimed_test_count_matches_the_suite -q` → 1 passed.

The reword is historically accurate ("the suite then held 483 tests") and is not a guard dodge — it
removes a claim that was false at the time it was recorded, rather than masking a stale number.

### Finding 2 (LOW, informational) — the mutation tool loaded under its own name: FIXED, mutation-proved

`tests/bowen/test_ensemble_record.py:51-56` now loads `tools/mutation_record.py` under its real module
name (`spec_from_file_location("tools.mutation_record", …)`) and removes the second
`sys.modules["tools.mutation_record"] = _mutants` alias line, so the module's `__name__` matches the name
it is registered under. `test_sweep_tool_shares_the_loaded_mutation_tool` (`:138-141`) now also asserts
`_mutants.__name__ == "tools.mutation_record" and sys.modules["tools.mutation_record"] is _mutants`.

- The single-load property is preserved: the sweep tool's `from tools.mutation_record import …`
  (`tools/sweep_record.py:30`) resolves to the already-loaded copy, so there is still one copy, not two.
- **Mutation-proved** against the real file: reverting the name to `"mutation_record_tool"` (and thereby
  losing the real-name registration, recreating the two-copy state) turns the test red at `:140` with
  `_sweep.Mutant is not _mutants.Mutant` (two distinct `Mutant` classes). The file was restored and the
  test passes again (`1 passed`, `git status` clean).
- `grep -rn "mutation_record_tool"` returns nothing anywhere in the tree; the stray alias string is gone.
