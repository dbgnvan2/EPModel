## 3. The tooling: version 2's dispositions

`docs/version_1_dispositions.md` is frozen at the tag (`tests/test_version_1_status.py::FROZEN`), and
`tools/version_2_status.py` has no way to record the owner's review of a changed verdict, so `M11.C.21` and
`M11.C.34` could never be final even after the owner reviews them. **(R)** A new file,
`docs/version_2_dispositions.md`, in the same table form, read after version 1's and taking precedence on a key it
names; a new kind, `verdict reviewed`, which clears the "changed since the tag" block on a row whose current verdict it
names; and `accepted finding` for `M11.C.49` and, if it fails, `M11.C.48`. A row Claude writes carries `decided`
"Claude's recommendation 2026-10-29, pending the owner's review", which the tool reads as not the owner's, so the row
stays unmet under W1 until the owner changes it. No engine file changes.

Tests (`tests/test_version_2_status.py`):

- `test_w1_v2_disposition_takes_precedence_over_version_1` — a version 2 row on a key version 1 also names wins.
- `test_w1_v2_verdict_reviewed_by_the_owner_makes_a_changed_verdict_final` — and one not the owner's leaves it unmet.
- `test_w1_v2_verdict_reviewed_names_the_verdict_it_reviewed` — a review of PASS does not clear a row now FAIL.
- `test_w1_v2_dispositions_parse_strictly` — an unknown kind or criterion raises, as version 1's do.

Each proved by mutation before it counts (a mutant of the reader that ignores precedence, or ignores the verdict named).
